# TIBCO Platform 1.19.0 CP and DP Setup on AKS

Use this guide as the 1.19.0 overlay for the shared AKS CP+DP setup. The common AKS preparation flow (AKS cluster, ingress/storage, PostgreSQL, DNS, certificates) remains in the [shared baseline guide](../how-to-cp-and-dp-aks-setup-guide).

1.19.0 is the mandatory intermediate step between 1.18.0 and the current 1.20.0 release. For new installations go straight to the [1.20.0 overlay](../v1.20/how-to-cp-and-dp-aks-setup-guide).

## Start Here

1. Complete the shared baseline guide: [../how-to-cp-and-dp-aks-setup-guide.md](../how-to-cp-and-dp-aks-setup-guide).
2. Use 1.18.0 as the direct upgrade source: [1.18.0 release notes](../../releases/v1.18.0).
3. Apply the 1.19.0-specific changes below, then continue with the [1.20.0 overlay](../v1.20/how-to-cp-and-dp-aks-setup-guide).

```bash
helm repo add tibco-platform https://tibcosoftware.github.io/tp-helm-charts
helm repo update tibco-platform
```

## AKS Changes from 1.18.0

### Control Plane Base Chart

```bash
export TP_CP_BASE_CHART_VERSION="1.19.0"

helm upgrade --install --wait --timeout 1h \
  -n ${CP_INSTANCE_ID}-ns platform-base tibco-cp-base \
  --labels layer=5 \
  --repo "${TP_TIBCO_HELM_CHART_REPO}" \
  --version "${TP_CP_BASE_CHART_VERSION}" \
  --values cp-values.yaml
```

Or run the assistant from `tp-helm-charts`, which validates that the release is `deployed` at `app_version` 1.18.0:

```bash
cd tp-helm-charts/scripts/1.19.0 && ./upgrade.sh
```

### Remove `createDeprecatedPolicies`

`tibco-cp-base` 1.19.0 removes `global.tibco.networkPolicy.createDeprecatedPolicies` and the deprecated policy templates. Delete the key from `cp-values*.yaml`:

```yaml
global:
  tibco:
    networkPolicy:
      # createDeprecatedPolicies: true   # REMOVED in 1.19.0
      createClusterScopePolicies: true
```

The upgrade assistant does not remove it for you.

### otel-collector Default

The chart default for `otel-collector.enabled` changes from `false` to `true` in 1.19.0 (and back to `false` in 1.20.0). The shared guide sets it explicitly to `true`. If your values file omits the key and you have no log server, add `otel-collector.enabled: false` before upgrading.

### Jaeger v2

The observability recipe moves Jaeger from chart 0.72.41 (Jaeger 1.66.0) to chart 4.8.2 (Jaeger 2.19.0) and OpenTelemetry Collector to 0.156.2. Traces recorded before the upgrade appear as red dots (PCP-20148). Elasticsearch 8.15.2 and OpenSearch 2.14.0 remain the tested backends.

### Elasticsearch Log Export After Upgrade (PCP-23331)

On self-hosted Control Planes, CP service logs can stop reaching Elasticsearch after the 1.18.0 to 1.19.0 upgrade (`document_parsing_exception`, HTTP 400). Workaround:

```bash
kubectl edit configmap otel-services -n ${CP_INSTANCE_ID}-ns
# 1. under exporters.elasticsearch/log set   mapping: { mode: none }
# 2. remove transform/es-bodymap from service.pipelines.logs.processors
kubectl rollout restart deployment cp-otel-services -n ${CP_INSTANCE_ID}-ns
```

Fixed in 1.20.0.

### Gateway API: hybrid-proxy Route Fixed

`tibco-cp-base` 1.19.0 changes the `hybrid-proxy` HTTPRoute template: it always renders `PathPrefix: /infra/tunnel` and only adds `PathPrefix: /` when `dnsDomain != dnsTunnelDomain` (fixes PCP-21362). With simplified DNS both `hybrid-proxy` and `router-operator` HTTPRoutes can use `*.<base-domain>` on the same Gateway. The chart never reads `gatewayRoute.rules`, so remove the explicit rules from the 1.18 workaround. See the [1.20.0 overlay](../v1.20/how-to-cp-and-dp-aks-setup-guide#gateway-api-hybrid-proxy-route-fixed-since-1190) for the values snippet.

### Data Plane Infrastructure

Use the commands generated by the Control Plane UI (`dp-configure-namespace` 1.19.10, `dp-core-infrastructure` 1.19.5). `dp-configure-namespace` 1.19.10 removes `networkPolicy.createDeprecatedPolicies` and adds RBAC for the Infra MCP Server, MCP Gateway, and Spring Boot (`rbac.infraMcp`, `rbac.infraMcpClusterScoped`, `rbac.infraMcpServiceAccountName`, `rbac.infraMcpExtraRules`, `rbac.mcpGateway`, `rbac.springboot`).

### Infra MCP Server Capability

The TIBCO Platform Infra MCP Server can be provisioned from Data Planes > Capabilities > Add Capability. It provides read-only `kubectl get/describe/logs` and `helm list/status/get/history` through the Data Plane proxy. It exists to serve TESSA, which in 1.19.0 is only available on TIBCO Operated Control Plane (US region), so it is optional for self-hosted AKS.

### Flogo App-Init Resources

If Flogo app pods are slow to start on smaller node pools, tune the new `flogoprovisioner` chart `config` values `APP_INIT_CPU_REQUEST` (100m), `APP_INIT_MEMORY_REQUEST` (100Mi), `APP_INIT_CPU_LIMIT` (200m), `APP_INIT_MEMORY_LIMIT` (400Mi).

### Developer Hub Storage

Use the Azure Disk class for the Developer Hub PostgreSQL pod; `azure-files-sc` fails on `chmod` (PLTDX-1343).

### Email, DNS

Unchanged from 1.18.0: email is configured in the Platform Console (MailDev host `development-mailserver.tibco-ext.svc.cluster.local`, port `1025`), and simplified DNS uses one base domain with one wildcard certificate.

## Upgrade Checklist from 1.18.0

- [ ] Back up Helm values, secrets, and database state.
- [ ] Remove `createDeprecatedPolicies`; set `otel-collector.enabled` explicitly.
- [ ] Upgrade `tibco-cp-base` to 1.19.0.
- [ ] Upgrade BW, Flogo, Developer Hub to 1.19.0; Hawk and Messaging to 1.19.23.
- [ ] Upgrade Data Plane infrastructure (`dp-configure-namespace` 1.19.10, `dp-core-infrastructure` 1.19.5), then capabilities.
- [ ] CP logs still arrive in Elasticsearch (apply the PCP-23331 workaround if not).
- [ ] Validate HTTPRoutes if Gateway API is used.
- [ ] Continue to [1.20.0](../v1.20/how-to-cp-and-dp-aks-setup-guide).

## Known Issues to Watch on AKS

- PCP-23331: CP logs stop reaching Elasticsearch after the upgrade (workaround above).
- PCP-20148: traces older than the Jaeger v2 move show as red dots.
- PCP-19687: cards show wrong data for Data Planes still on 1.18.0 until upgraded.
- PLTDX-1459: distinct FQDNs for CP and Developer Hub behind Traefik.
- PLTDX-1343: use Azure Disk, not `azure-files-sc`, for Developer Hub PostgreSQL.
