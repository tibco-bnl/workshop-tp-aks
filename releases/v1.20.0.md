# TIBCO Platform v1.20.0 Release Notes

**Release Date**: August 2026 (official documentation published August 31, 2026)
**TIBCO Platform Control Plane Version**: 1.20.0
**Status**: Current release
**Workshop documentation updated**: September 21, 2026

## Overview

TIBCO Platform Control Plane v1.20.0 adds Control Plane rollback, OTLP exporters with custom headers, dedicated Kubernetes Jobs for Flogo builds, the Developer Hub MCP Catalog, and MCP Hub (Preview, TIBCO Operated Control Plane only). This workshop skipped the intermediate 1.19.0 release when it shipped; it is documented in the [v1.19.0 release notes](./v1.19.0) because every 1.18.0 environment must pass through 1.19.0 on the way to 1.20.0.

For self-hosted AKS deployments the most important operator-facing changes are in the `tibco-cp-base` chart: `global.tibco.networkPolicy.createDeprecatedPolicies` is gone (1.19.0), `global.tibco.disabledInfraCapabilities` is new (1.20.0), the `otel-collector` default changed twice, and the Gateway API hybrid-proxy route is fixed (1.19.0). This release is aligned with the 1.20.0 chart artifacts in the official [TIBCO tp-helm-charts repository](https://github.com/TIBCOSoftware/tp-helm-charts).

## What's New in v1.20.0

### TIBCO Control Plane

#### Control Plane Rollback

If an upgrade fails, the Control Plane can be rolled back to the version it was upgraded from. With `global.tibco.manageDbSchema: true` (workshop default) one `helm rollback <release> <revision> -n <namespace> --wait` reverts release and database schema. With `manageDbSchema: false`, run `postgres-helper.bash rollbackDbSchema <chart-version>` from the `tp-helm-charts` database scripts first. TIBCO recommends rolling back the Control Plane before upgrading any Data Plane or capability.

#### OTLP Exporter with Custom Headers

OTLP (http and grpc) exporters and query services for logs, metrics, and traces accept custom header key/value pairs. The secondary exporter supports OTLP only.

#### MCP Hub (Preview)

MCP Hub is the central console for Model Context Protocol infrastructure with a built-in MCP Gateway (guardrails, plugins, virtual tools, virtual servers). It is available in TIBCO Operated Control Plane only. The gateway runtime is delivered as the new `tp-mcp-gateway` Data Plane chart (Full mode PostgreSQL plus Redis, Lite mode SQLite). Self-hosted Control Planes on AKS cannot use MCP Hub in 1.20.0.

### Flogo Capability

- Application builds run in dedicated Kubernetes Jobs with their own CPU, memory, queue, and timeout settings: `FLOGO_APP_BUILD_CPU_REQUEST`, `FLOGO_APP_BUILD_CPU_LIMIT`, `FLOGO_APP_BUILD_MEMORY_REQUEST`, `FLOGO_APP_BUILD_MEMORY_LIMIT`, `FLOGO_APP_BUILD_TIMEOUT_SECONDS`, `FLOGO_APP_BUILD_MAX_QUEUED_SECONDS`.

### Developer Hub

- MCP Catalog registers MCP servers as Backstage API entities (`spec.type: mcp-server`); requires Backstage 1.51.0+ (shipped with 1.19.0) and Advanced navigation mode.

### BusinessWorks 5 and Adapters (Control Tower)

- Bulk suspend/resume of process starters; pagination, sorting, and Kill/Suspend/Resume/Export actions on the Active Processes and Locks tabs.

### Messaging

- No 1.20.0 EMS or ActiveSpaces charts were published in `tp-helm-charts`; the latest messaging charts remain 1.19.23. The official compatibility matrix lists EMS 1.19.0 as the latest row.

### Deprecated and Removed

- NGINX Ingress Controller support is removed. TIBCO no longer officially supports or recommends its use with Control Plane and Data Planes (wording unchanged since 1.18.0). AKS workshops already standardize on Traefik.

## Chart Changes That Affect AKS Values Files

From the `tibco-cp-base` chart source (tags `tibco-cp-base-1.18.0`, `-1.19.0`, `-1.20.0`) in `tp-helm-charts`:

| Value | 1.18.0 | 1.19.0 | 1.20.0 | Action |
|-------|--------|--------|--------|--------|
| `global.tibco.networkPolicy.createDeprecatedPolicies` | `true` | removed | removed | Delete from `cp-values*.yaml` before upgrading to 1.19.0 or later |
| `otel-collector.enabled` (chart default) | `false` | `true` | `false` | Set explicitly. The 1.20.0 chart disables it so a log server is not a prerequisite; enable only with a reachable Elasticsearch/OpenSearch log server |
| `global.tibco.disabledInfraCapabilities` | n/a | n/a | `[MFTADAPTER]` | New. Capability IDs removed from every Data Plane type's mandatory infra capability list. MFT off by default; set `[]` to enable all |
| `hybrid-proxy.gatewayRoute` HTTPRoute rules | `/` only (PCP-21362) | `/infra/tunnel` always; `/` only when `dnsDomain != dnsTunnelDomain` | same | Simplified DNS with Gateway API no longer needs hostname separation |
| Fluent Bit sidecar tag | 5.0.6 | 5.0.9 | 5.1.0 | Informational |

`scripts/1.20.0/upgrade.sh` in `tp-helm-charts` performs no value transformations; it validates that the release is `deployed` at `app_version` 1.19.0, copies values, and runs `helm upgrade` to chart 1.20.0.

## AKS-Specific Considerations

### Simplified DNS and Gateway API with Traefik or NGINX Gateway Fabric

Simplified DNS remains the recommended AKS pattern. Since `tibco-cp-base` 1.19.0 the `hybrid-proxy` HTTPRoute renders `PathPrefix: /infra/tunnel` itself and omits the catch-all `/` when `dnsDomain == dnsTunnelDomain`, so both `hybrid-proxy` and `router-operator` can attach to `*.<base-domain>` on the same Gateway. The chart never consumed a `gatewayRoute.rules` value; remove explicit rules left over from the 1.18 workaround.

### otel-collector and the Log Server

The workshop `cp-values*.yaml` files set `otel-collector.enabled: true` explicitly. If you rely on the chart default instead, it is `false` in 1.20.0. Enable it only when an Elasticsearch or OpenSearch log server is reachable from the Control Plane namespace.

### Developer Hub Storage on Azure

Known issue PLTDX-1343: with `azure-files-sc` the Developer Hub PostgreSQL pod fails on `chmod`. Use `azure-disk-sc` (or the workshop's `managed-premium` Azure Disk class) for Developer Hub database storage.

### Email with MailDev

Unchanged since 1.18.0: keep MailDev running and enter `development-mailserver.tibco-ext.svc.cluster.local:1025` in the Platform Console. Do not add email Helm values.

### Infra MCP Server and MCP Gateway RBAC

`dp-configure-namespace` 1.19.10 and later create RBAC for the Infra MCP Server and MCP Gateway capabilities (`rbac.infraMcp`, `rbac.mcpGateway`, `rbac.springboot`, default `true`). Cluster-scoped diagnostics require `rbac.infraMcpClusterScoped=true`. TESSA, which consumes the Infra MCP Server, is only available on TIBCO Operated Control Plane (US region).

## Upgrade Path from v1.19.0

1. Back up Helm values, `session-keys` and `cporch-encryption-secret`, and PostgreSQL data. Record `helm history platform-base -n ${CP_INSTANCE_ID}-ns`.
2. Update the `tibco-platform` Helm repository.
3. Confirm `createDeprecatedPolicies` is absent and set `otel-collector.enabled` and `global.tibco.disabledInfraCapabilities` intentionally.
4. Upgrade `tibco-cp-base` to 1.20.0 or run `scripts/1.20.0/upgrade.sh` from `tp-helm-charts`.
5. Upgrade capability charts to 1.20.0 (`tibco-cp-bw`, `tibco-cp-flogo`, `tibco-cp-devhub`; `tibco-cp-hawk --version '1.20.*'`). Leave `tibco-cp-messaging` at 1.19.23.
6. Upgrade Data Plane infrastructure from the Control Plane UI (`dp-configure-namespace` 1.20.0, `dp-core-infrastructure` 1.20.3), then capabilities. The official matrix requires DP 1.20.0 and CP 1.20.0 for Flogo, BW5CE, BW6CE, and Developer Hub 1.20.0.
7. Validate with `scripts/verify-release.sh` from `tp-helm-charts` (`CHECK_RELEASE_FOLDER=control-plane`, `CHECK_RELEASE_VERSION=1.20.0`).

## Upgrade Path from v1.18.0

Direct 1.18.0 to 1.20.0 upgrades are not supported by the upgrade assistants (`scripts/1.19.0/upgrade.sh` requires `app_version` 1.18.0, `scripts/1.20.0/upgrade.sh` requires 1.19.0). Upgrade to 1.19.0 first:

1. Follow the [v1.19.0 upgrade path](./v1.19.0#upgrade-path-from-v1180).
2. Apply the v1.20.0 upgrade path above.

Alternatively use the sequential master script documented in `scripts/MASTER-UPGRADE-README.md` in `tp-helm-charts`.

## Known Issues to Review

New in 1.20.0:

- **PCP-23615:** after upgrading to 1.20.0, deleting a Data Plane's observability configuration fails. No workaround.
- **FLOGO-18866:** WebSocket application public endpoint URLs are shown with `https://`; use `wss://`.

Carried over and relevant to AKS, Traefik, and Gateway API users:

- **PCP-20148:** traces recorded before the Jaeger v2 move (1.19.0) appear as red dots.
- **PCP-19820:** traces and application service metrics do not work with Traefik ingress in Control Tower Data Planes on TIBCO Operated Control Plane.
- **PCP-19687:** cards show wrong data for Data Planes still on the previous release until they are upgraded.
- **PCP-17037 / PCP-9344 / BWCE-8521:** upgrading infrastructure without capabilities breaks Helm-managed deployments and hides endpoints and metrics.
- **BWCE-11307:** Swagger tester is inaccessible for BW6 apps created on 1.17.0 and exposed via `traefik-gateway`; upgrade capability and app.
- **PLTDX-1459:** Control Plane and Developer Hub on the same cluster with Traefik and the same hostname return 404; use distinct FQDNs.
- **PLTDX-1343:** `azure-files-sc` breaks the Developer Hub PostgreSQL pod; use `azure-disk-sc`.

Closed in 1.20.0: PCP-23331 (CP logs stopped reaching Elasticsearch after the 1.19.0 upgrade) and PCP-20976 (BW6 agent auto-switching with NGINX ingress and NetScaler).

Review the complete official list before production upgrades: [Official 1.20.0 Known Issues](https://docs.tibco.com/pub/platform-cp/1.20.0/doc/html/Release-Notes/known-issues.htm).
